DOCKER IMAGE DETAILS:
====================

Base Image: node:20-slim (Debian Bookworm)
Alternative: node:20-alpine
Image Size: ~500MB (Debian) / ~400MB (Alpine)
Memory Usage: 200-400MB during operation
Exposed Ports: 3000/tcp

Build Stages:
1. Builder - Full build environment with Python, G++, Make, Git
2. Runtime - Minimal production environment

Volumes:
- ./baileys_auth_info:/app/baileys_auth_info (authentication data)
- ./logs:/app/logs (application logs)

USAGE:
======

Quick Start:
  docker compose build
  docker compose up -d
  docker compose logs -f baileys

Using Makefile:
  make build
  make up
  make logs

Manual Docker:
  docker build -t baileys .
  docker run -it -p 3000:3000 -v $(pwd)/baileys_auth_info:/app/baileys_auth_info baileys

API ACCESS:
===========

The container exposes port 3000 which is accessible from the host machine.
This allows for:
- Future REST API implementations
- WebSocket connections
- Health check endpoints
- Custom integrations

PERSISTENCE:
============

Authentication data persists across container restarts via volume mounts.
Users stay logged in even after:
- Container restarts
- Host machine reboots  
- Docker daemon restarts

SECURITY NOTES:
===============

- Session data in baileys_auth_info/ must not be committed to git
- .env file should contain sensitive configuration
- Container runs as non-root user
- Minimal attack surface in production image
- Regular dependency updates recommended

MAINTENANCE:
============

Update dependencies:
  docker compose build --no-cache
  docker compose up -d

Backup authentication:
  tar -czf backup.tar.gz baileys_auth_info/

Clean everything:
  make clean
  # or
  docker compose down -v
